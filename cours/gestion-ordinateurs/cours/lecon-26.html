Leçon 26

Utilisateurs, groupes et permissions Linux

Cours : Gestion d’ordinateurs — Administration Linux
Niveau : Débutant à intermédiaire

Méthode pédagogique : Théorie, démonstrations, commandes Linux, manipulations guidées et exercices après chaque concept.

Objectifs pédagogiques

  • Expliquer le fonctionnement des utilisateurs et des groupes.
  • Distinguer un utilisateur standard de root.
  • Utiliser sudo pour les opérations administratives.
  • Créer des comptes et gérer les groupes.
  • Identifier et modifier les propriétaires.
  • Interpréter les permissions de lecture, écriture et exécution.
  • Utiliser chmod, chown et chgrp.
  • Vérifier les droits et diagnostiquer les problèmes d’accès.

1. Groupe — Concept fondamental

1.1 Définition

Dans Linux, un groupe représente un ensemble d’utilisateurs partageant certains droits d’accès à des ressources du système. Les groupes permettent d’organiser les utilisateurs et de simplifier la gestion des autorisations.

  • Un groupe principal, associé par défaut au compte.
  • Zéro, un ou plusieurs groupes secondaires, permettant d’accéder à des ressources supplémentaires.

1.2 Pourquoi utiliser des groupes ?

Dans une entreprise, alice et bob sont développeurs, tandis que charlie travaille en comptabilité. Un groupe developpeurs permet à Alice et Bob de partager des ressources sans les rendre accessibles à Charlie.

Groupe : developpeurs
↙         ↘
alicebob

1.3 Identifier les groupes

groups
groups alice
id alice

1.4 Exemple d’exécution

$ id alice
uid=1001(alice) gid=1001(alice) groups=1001(alice),1003(developpeurs)

Alice possède l’UID 1001, le groupe principal alice et le groupe secondaire developpeurs.

2. root — Administrateur du système

2.1 Définition

root est le compte administrateur principal de Linux. Son identifiant est UID 0. Il peut notamment installer des logiciels, gérer les comptes et configurer le système. Certaines restrictions techniques ou de sécurité peuvent néanmoins s’appliquer.

2.2 Utilisateur standard et root

Utilisateur standardroot
Accès limité aux ressourcesPrivilèges administratifs étendus
Travaille principalement sur ses fichiersPeut administrer les fichiers système
Ne crée normalement pas de comptesPeut créer et supprimer des comptes
Ne modifie pas librement la configurationPeut configurer les services système

2.3 Identifier l’utilisateur courant

whoami
id -u

Un UID égal à 0 correspond à l’identité administrative root.

2.4 Ouvrir une session administrative

sudo -i
exit

Il est recommandé de travailler au quotidien avec un compte standard et de n’obtenir des privilèges élevés que lorsque cela est nécessaire.

3. sudo — Exécution de commandes administratives

3.1 Définition

sudo (superuser do) permet à un utilisateur autorisé d’exécuter une commande avec les privilèges d’un autre utilisateur, généralement root.

3.2 Syntaxe générale

sudo commande [options] [arguments]

Exemple : sudo apt update actualise la liste des paquets sur les systèmes utilisant APT.

3.3 Exemples

CommandeFonction
sudo apt updateActualiser la liste des paquets
sudo apt install treeInstaller tree
sudo adduser testuserCréer un compte (systèmes compatibles)
sudo -lAfficher les autorisations sudo
sudo -iOuvrir une session administrateur

3.4 Différence entre sudo et root

root est un compte administratif ; sudo est un mécanisme d’élévation contrôlée des privilèges.

3.5 Manipulation guidée

whoami
sudo whoami
whoami

Pour une session alice, les résultats attendus sont :

alice
root
alice

4. Création d’utilisateurs

4.1 Définition et rôle d’un compte utilisateur

Un compte utilisateur est une identité permettant à une personne ou à un service d’accéder aux ressources Linux. Il est caractérisé notamment par un nom de connexion, un identifiant numérique (UID), un groupe principal (GID), un répertoire personnel et un interpréteur de commandes (shell). La gestion des comptes comprend leur création, modification, activation, désactivation et suppression.

4.2 Informations d’un compte

Le fichier /etc/passwd contient les informations générales des comptes :

alice:x:1001:1001:Alice:/home/alice:/bin/bash
ChampSignification
aliceNom de connexion
xMot de passe chiffré généralement stocké dans /etc/shadow
1001 (3e champ)UID
1001 (4e champ)GID principal
AliceChamp descriptif
/home/aliceRépertoire personnel
/bin/bashShell de connexion

Le fichier /etc/shadow contient les informations relatives aux mots de passe et à leur expiration ; son accès est restreint.

4.3 Création d’un utilisateur avec adduser

Sur Ubuntu et Debian, adduser fournit une procédure interactive de création : création du compte, configuration du répertoire personnel et définition du mot de passe.

sudo adduser alice

Vérification :

id alice
getent passwd alice
ls -ld /home/alice

4.4 Création d’un utilisateur avec useradd

useradd permet une création plus explicite, notamment dans les scripts d’administration.

sudo useradd -m -s /bin/bash bob
sudo passwd bob
  • -m : crée le répertoire personnel.
  • -s /bin/bash : définit Bash comme shell.
  • passwd bob : définit le mot de passe de Bob.

Selon la distribution, useradd peut avoir des valeurs par défaut différentes ; contrairement à adduser sur Ubuntu/Debian, il ne propose pas nécessairement un assistant interactif.

4.5 Modification du nom d’utilisateur

La commande usermod -l permet de changer le nom de connexion. Le compte conserve normalement son UID et ses appartenances aux groupes.

sudo usermod -l alice2 alice

Cette commande renomme alice en alice2, mais ne renomme pas automatiquement son répertoire personnel. Si l’on souhaite aussi le déplacer :

sudo usermod -d /home/alice2 -m alice2

Vérification :

id alice2
getent passwd alice2
ls -ld /home/alice2
Précaution : effectuez le renommage depuis un autre compte administrateur, lorsque l’utilisateur concerné n’a plus de session ni de processus actifs. Les chemins externes, scripts et configurations faisant référence à l’ancien nom peuvent nécessiter une mise à jour.

4.6 Modification du mot de passe

La commande passwd sert à définir ou à modifier un mot de passe.

passwd                 # Modifier son propre mot de passe
sudo passwd alice2     # Réinitialiser celui d’un autre compte

La saisie du mot de passe ne s’affiche généralement pas à l’écran. L’administrateur doit privilégier des mots de passe robustes et ne pas les écrire directement dans des scripts ou dans l’historique du terminal.

Pour demander à l’utilisateur de changer son mot de passe lors de sa prochaine connexion :

sudo passwd -e alice2

4.7 Désactivation d’un compte utilisateur

Deux mécanismes doivent être distingués : le verrouillage du mot de passe et l’expiration du compte.

A. Verrouiller l’authentification par mot de passe :

sudo passwd -l alice2

Cette opération empêche normalement l’authentification à l’aide du mot de passe Unix, mais elle ne bloque pas nécessairement d’autres méthodes, comme certaines connexions SSH par clé.

B. Faire expirer le compte :

sudo usermod --expiredate 1 alice2

Cette commande définit une date d’expiration passée (le 2 janvier 1970), ce qui rend le compte expiré pour les mécanismes de connexion qui respectent cette information. Le comportement exact dépend des services d’authentification configurés.

Vérifier l’état :

sudo passwd -S alice2
sudo chage -l alice2

4.8 Réactivation d’un compte utilisateur

Pour annuler l’expiration du compte :

sudo usermod --expiredate -1 alice2

Si le mot de passe a été verrouillé avec passwd -l, on peut le déverrouiller lorsque le compte possède déjà un mot de passe valide :

sudo passwd -u alice2

Si le compte ne dispose pas d’un mot de passe utilisable, il peut être nécessaire d’en définir un :

sudo passwd alice2

Vérifiez ensuite les états du mot de passe et du compte avec passwd -S et chage -l. Réactiver un compte ne garantit pas automatiquement l’accès si d’autres restrictions sont présentes.

4.9 Suppression d’un utilisateur

La suppression d’un compte doit être effectuée après vérification de ses données, de ses processus et de ses éventuelles responsabilités sur le système.

A. Supprimer le compte sans supprimer automatiquement son répertoire personnel :

sudo userdel bob

B. Supprimer le compte et les fichiers personnels pris en charge par l’option -r :

sudo userdel -r bob
Attention : userdel -r peut supprimer définitivement le répertoire personnel et la boîte aux lettres locale. Les fichiers appartenant à l’utilisateur et situés ailleurs ne sont pas nécessairement supprimés. Sauvegardez les données utiles avant toute suppression.

Vérification :

getent passwd bob
id bob

Si le compte a bien été supprimé, ces commandes ne doivent plus retrouver l’identité locale correspondante (sauf présence d’une autre source d’identité configurée).

4.11 Manipulation guidée — Cycle de vie d’un compte

Sur une machine virtuelle de laboratoire, depuis un compte disposant de sudo :

sudo useradd -m -s /bin/bash stagiaire
sudo passwd stagiaire
id stagiaire
sudo usermod -l stagiaire2 stagiaire
sudo usermod -d /home/stagiaire2 -m stagiaire2
sudo passwd stagiaire2
sudo passwd -l stagiaire2
sudo passwd -S stagiaire2
sudo usermod --expiredate 1 stagiaire2
sudo chage -l stagiaire2
sudo usermod --expiredate -1 stagiaire2
sudo passwd -u stagiaire2
sudo chage -l stagiaire2
getent passwd stagiaire2

Les étudiants doivent relever l’état du compte après chaque étape. La suppression éventuelle du compte de test sera effectuée uniquement après validation des résultats et des sauvegardes nécessaires.

5. Groupes — Administration

5.1 Création d’un groupe

sudo groupadd developpeurs

5.2 Ajouter un utilisateur à un groupe

sudo usermod -aG developpeurs alice

-G définit les groupes secondaires et -a ajoute sans remplacer les appartenances existantes.

5.3 Retirer un utilisateur d’un groupe

sudo gpasswd -d alice developpeurs

5.4 Supprimer un groupe

sudo groupdel developpeurs

Ne supprimez pas un groupe encore nécessaire, notamment s’il est principal pour un compte.

5.5 Consulter les groupes

getent group developpeurs
developpeurs:x:1003:alice,bob

La liste finale indique les membres secondaires enregistrés, pas nécessairement tous les membres ayant ce groupe comme groupe principal.

5.6 Manipulation guidée

sudo groupadd projetweb
sudo usermod -aG projetweb etudiant1
sudo usermod -aG projetweb etudiant2
getent group projetweb
id etudiant1

Une nouvelle connexion peut être nécessaire pour que les groupes soient pris en compte dans la session.

6. Propriétaire — Appartenance des fichiers et répertoires

6.1 Définition

Chaque fichier et répertoire possède un utilisateur propriétaire et un groupe propriétaire. Ils participent à la détermination des droits d’accès.

6.2 Exemple

touch rapport.txt
ls -l rapport.txt
-rw-r--r-- 1 alice developpeurs 0 Nov 3 10:30 rapport.txt

alicePropriétaire
developpeursGroupe propriétaire
0Taille en octets
Nov 3 10:30Date de modification
rapport.txtNom du fichier

6.3 Pourquoi définir un propriétaire ?

La propriété permet de contrôler l’administration des permissions. Les fichiers système appartiennent souvent à root afin de limiter les modifications par les comptes ordinaires.

6.4 Vérifier le propriétaire

ls -l rapport.txt
ls -ld /home/alice

L’option -d affiche les informations du répertoire lui-même.

7. Permissions Linux

7.1 Définition

Les permissions Linux déterminent les opérations autorisées sur les fichiers et répertoires. Le modèle classique distingue trois catégories :

CatégorieSymboleDescription
PropriétaireuUtilisateur propriétaire
GroupegGroupe propriétaire
AutresoAutres utilisateurs

7.2 Structure des permissions

-rwxr-xr--
-TyperwxPropriétairer-xGrouper--Autres
  • Le propriétaire peut lire, écrire et exécuter.
  • Le groupe peut lire et exécuter.
  • Les autres peuvent seulement lire.

7.3 Afficher les permissions

ls -l
ls -la

L’option -a inclut les fichiers cachés.

7.4 Permissions et sécurité

Le principe du moindre privilège consiste à n’attribuer que les droits nécessaires.

9. chmod — Modifier les permissions

9.1 Définition

chmod (change mode) modifie les permissions. Le propriétaire ou un processus suffisamment privilégié peut normalement les changer.

9.2 Syntaxe générale

chmod [options] mode fichier

9.3 Méthode symbolique

  • u, g, o, a : catégories.
  • + : ajouter ; - : retirer ; = : définir exactement.
chmod u+x script.sh
chmod g+w rapport.txt
chmod o-r rapport.txt
chmod u=rw,g=r,o= rapport.txt

9.4 Méthode numérique

chmod 755 script.sh
-rwxr-xr-x
CommandePermissions
chmod 600 fichier.txtrw-------
chmod 644 fichier.txtrw-r--r--
chmod 700 script.shrwx------
chmod 750 script.shrwxr-x---

9.5 Modification récursive

chmod -R 750 dossier/

Attention : attribuer le droit d’exécution à tous les fichiers ordinaires n’est généralement pas souhaitable.

9.6 Manipulation guidée

touch rapport.txt
chmod 640 rapport.txt
ls -l rapport.txt
-rw-r-----

10. chown — Modifier le propriétaire

10.1 Définition

chown (change owner) modifie l’utilisateur propriétaire et peut également changer le groupe propriétaire.

10.2 Syntaxe

chown [options] utilisateur fichier
chown utilisateur:groupe fichier

10.3 Exemples

sudo chown alice rapport.txt
sudo chown alice:developpeurs rapport.txt
sudo chown -R alice:developpeurs projet/

Le caractère : sépare l’utilisateur du groupe.

10.4 Pourquoi utiliser chown ?

Pour transférer un fichier à un autre utilisateur ou placer un répertoire sous la responsabilité d’un compte. La modification du propriétaire requiert généralement des privilèges administratifs.

10.5 Manipulation guidée

touch rapport.txt
ls -l rapport.txt
sudo chown etudiant1 rapport.txt
ls -l rapport.txt

11. chgrp — Modifier le groupe propriétaire

11.1 Définition

chgrp (change group) modifie uniquement le groupe propriétaire d’un fichier ou répertoire.

11.2 Syntaxe

chgrp [options] groupe fichier

11.3 Exemple

sudo chgrp developpement rapport.txt

11.4 Modification récursive

sudo chgrp -R developpement projet/

11.5 Comparaison

CommandeFonction
chown alice fichierModifier l’utilisateur propriétaire
chown alice:groupe fichierModifier utilisateur et groupe
chgrp groupe fichierModifier uniquement le groupe

Sous certaines conditions, un utilisateur peut changer le groupe d’un fichier lui appartenant vers un groupe dont il est membre.

11.6 Manipulation guidée

touch partage.txt
sudo chgrp developpement partage.txt
ls -l partage.txt

13. Travaux pratiques de synthèse

Mise en situation : Administration d’un espace de travail partagé

Une entreprise souhaite configurer un environnement Linux pour une équipe de développement. dev1 et dev2 doivent partager un répertoire ; les autres utilisateurs ne doivent pas accéder à son contenu.

Travail demandé

  1. Créez les comptes dev1 et dev2.
  2. Créez un groupe equipe_dev.
  3. Ajoutez les deux utilisateurs au groupe.
  4. Créez un répertoire /srv/projet_dev.
  5. Attribuez le groupe propriétaire equipe_dev au répertoire.
  6. Autorisez propriétaire et groupe à accéder au répertoire, sans accès aux autres.
  7. Configurez l’héritage du groupe pour les nouveaux éléments.
  8. Créez README.txt dans le répertoire.
  9. Vérifiez propriétaires et permissions.
  10. Expliquez comment tester les accès avec les deux utilisateurs.
