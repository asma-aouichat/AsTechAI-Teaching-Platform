Shell Linux et gestion des fichiers

Découvrir le terminal, le shell et son invite, naviguer dans Linux, manipuler les fichiers, utiliser les redirections, les pipes et le manuel.

Objectifs pédagogiques

À la fin de cette leçon, vous pourrez interpréter l’invite Linux, utiliser les chemins et les commandes de navigation et de gestion des fichiers, combiner des commandes avec les redirections et les pipes, et consulter le manuel Linux.

01Comprendre Linux, le terminal et le shell

Linux désigne une famille de systèmes d’exploitation construits autour du noyau Linux. On le retrouve notamment sur les serveurs, dans le cloud et les environnements de développement. Ubuntu, Debian, Fedora, Linux Mint et Kali Linux sont des distributions Linux.

Terminal

Application qui affiche une interface textuelle pour saisir des commandes et consulter leurs résultats.

Shell

Programme qui interprète les commandes de l’utilisateur. Bash est un shell très répandu.

Commande

Instruction donnée au système, souvent sous la forme commande [options] [arguments].

Exemple expliqué : ls -l Documents utilise la commande ls, l’option -l et l’argument Documents.

À tester dans le terminal
whoami
pwd
echo "Bonjour Linux"
À retenir : whoami affiche l’utilisateur connecté ; pwd affiche le dossier courant ; echo affiche le texte indiqué.

03Invite Linux (prompt)

L’invite de commande (prompt) est le texte affiché par le shell pour indiquer qu’il attend une instruction. Son apparence dépend de la configuration du système.

etudiant@ubuntu:~/Documents$
ÉlémentSignification
etudiantNom de l’utilisateur
ubuntuNom de la machine
~/DocumentsRépertoire courant (le symbole ~ désigne le dossier personnel)
$Invite habituelle d’un utilisateur ordinaire
#Souvent utilisé pour un shell administrateur (root)

Important : le signe $ affiché dans les tutoriels représente souvent l’invite ; il ne faut pas le saisir avec la commande.

À tester
whoami
hostname
pwd
Observation : comparez les informations obtenues avec celles de votre invite.

02Interface graphique et ligne de commande

Une interface graphique (GUI) utilise des fenêtres, des icônes et la souris. Une interface en ligne de commande (CLI) permet d’exécuter des opérations textuelles précises et répétables.

Interface graphiqueLigne de commande
Manipulation visuelleCommandes textuelles
Prise en main intuitiveSyntaxe à apprendre
Pratique pour parcourir des fichiersPratique pour automatiser et administrer à distance

Les deux approches sont complémentaires : le choix dépend de la tâche à accomplir.

À tester dans le terminal
pwd
ls
ls -l
À retenir : ls -l présente davantage d’informations que ls, notamment les permissions, le propriétaire et la taille.

03Arborescence et répertoires essentiels

Le système de fichiers Linux est organisé en arbre. La racine, notée /, se trouve au sommet de cette arborescence.

/├── home/│ └── etudiant/│ └── Documents/├── etc/├── usr/└── var/

/usrProgrammes et ressources partagées
/varDonnées variables, journaux

À tester dans le terminal
ls /
ls /home
À retenir : Le contenu exact varie selon la distribution et les comptes présents sur la machine.

04Chemins absolus et relatifs

Un chemin absolu commence à la racine /. Un chemin relatif part du répertoire courant.

Absolu

/home/etudiant/Documents/notes.txt

Relatif

Documents/notes.txt depuis /home/etudiant.

SymboleSignification
.Répertoire courant
..Répertoire parent
~Répertoire personnel
/Racine du système
cd -Retour au répertoire précédent

Application : depuis /home/etudiant/cours, le chemin relatif vers /home/etudiant/images est ../images.

À tester dans le terminal
cd ~
pwd
cd ..
cd /tmp
cd -
À retenir : Le chemin relatif dépend toujours de votre emplacement au moment de l’exécution.

05Se repérer et naviguer

pwd affiche le chemin du répertoire courant ; ls en liste les éléments ; cd permet de changer de dossier.

CommandeFonction

ls -aInclut les éléments cachés
ls -lhAffiche les tailles lisibles dans la liste détaillée
ls -laDétails et éléments cachés

À observer : les noms commençant par un point sont généralement cachés dans la liste standard.

À tester dans le terminal
pwd
ls
ls -l
ls -a
ls -lh
ls -la
cd ~
À retenir : Exemple de résultat de pwd : /home/etudiant (le nom du compte peut différer).

06Créer des dossiers et des fichiers

mkdir crée un répertoire. L’option -p crée au besoin les répertoires parents. touch crée un fichier vide s’il n’existe pas ou actualise son horodatage s’il existe.

Vous pouvez créer plusieurs fichiers en une seule commande en séparant leurs noms par des espaces.

À tester dans le terminal
cd ~
mkdir -p atelier/projets/linux
cd atelier
touch notes.txt
touch a.txt b.txt
ls -la
À retenir : Vérifiez d’abord le dossier courant avec pwd : une création s’effectue à l’emplacement indiqué.

07Copier, déplacer et renommer

cp crée une copie et conserve l’original. mv déplace un élément ou le renomme lorsque la destination est un nouveau nom.

OptionUtilité
-r avec cpCopie récursive d’un répertoire
-iDemande confirmation avant écrasement
-vAffiche les opérations effectuées

Une destination existante peut être écrasée : utilisez -i pendant les exercices.

À tester dans le terminal
cd ~/atelier
mkdir -p sauvegardes
cp -i notes.txt copie_notes.txt
cp -i notes.txt sauvegardes/
cp -r sauvegardes sauvegardes_backup
mv -i copie_notes.txt notes_finales.txt
mv -i notes_finales.txt sauvegardes/
À retenir : Après une copie, les deux fichiers existent ; après un déplacement, le fichier ne se trouve plus à son emplacement initial.

08Supprimer avec prudence

rm supprime des fichiers ; rmdir supprime uniquement un répertoire vide ; rm -r supprime un répertoire et son contenu de façon récursive.

Prudence : une suppression par rm ne passe généralement pas par la corbeille. L’option -f force certaines suppressions ; évitez-la lors des premières manipulations. Ne lancez jamais une suppression récursive sans vérifier sa cible.
À tester dans le terminal
cd ~/atelier
pwd
ls
touch a_supprimer.txt
rm -i a_supprimer.txt
mkdir dossier_vide
rmdir dossier_vide
À retenir : # Exemple à comprendre, sans l’exécuter : rm -r dossier supprimerait le dossier et son contenu.

09Lire le contenu d’un fichier

cat affiche directement le contenu d’un fichier court. less permet de parcourir un texte plus long : utilisez les flèches, la barre d’espace et la touche q pour quitter.

L’opérateur > redirige une sortie vers un fichier et remplace son contenu ; >> ajoute à la fin du fichier.

À tester dans le terminal
cd ~/atelier
echo "Ma première note Linux" > message.txt
cat message.txt
echo "Deuxième ligne" >> message.txt
less message.txt
À retenir : Après les deux commandes echo, le fichier contient deux lignes. La première commande aurait remplacé un éventuel contenu antérieur.

16Redirections : >, >> et <

Une redirection change la destination de la sortie d’une commande ou la source de son entrée. Elle permet notamment de sauvegarder le résultat d’une commande dans un fichier.

OpérateurRôleExemple
>Écrit dans un fichier en remplaçant son contenuecho Bonjour > note.txt
>>Ajoute du contenu à la finecho Linux >> note.txt
<Fournit un fichier comme entrée standardwc -l < note.txt
2>Redirige les messages d’erreurls absent 2> erreurs.txt
Exemple progressif
cd ~
mkdir -p linux_redirections
cd linux_redirections
echo "Première ligne" > notes.txt
echo "Deuxième ligne" >> notes.txt
cat notes.txt
wc -l < notes.txt

Résultat attendu : le fichier contient deux lignes et wc -l affiche 2.

Attention : > écrase le contenu existant. Vérifiez toujours le nom du fichier cible.

17Pipe (tube) : |

Le pipe, représenté par |, transmet la sortie standard d’une commande à l’entrée standard d’une autre. Il permet de combiner plusieurs traitements sans créer de fichier intermédiaire.

Syntaxe : commande1 | commande2

Exemples à tester
ls -l | less
printf "pomme\nbanane\npomme\n" | sort
printf "pomme\nbanane\npomme\n" | sort | uniq

Explication : ls -l | less permet de parcourir une liste détaillée ; sort trie les lignes ; uniq supprime les doublons consécutifs, d’où l’intérêt de trier avant.

À retenir : | transmet des données entre commandes ; > les enregistre dans un fichier. Dans less, appuyez sur q pour quitter.

18man : consulter le manuel Linux

La commande man ouvre la page de manuel d’une commande. Elle permet de découvrir sa description, sa syntaxe, ses options et parfois des exemples.

Syntaxe : man nom_commande

À tester dans le terminal
man ls
man cp
man man
ToucheAction
EspacePage suivante
bPage précédente
/motRecherche dans la page
nOccurrence suivante
qQuitter le manuel
À retenir : les pages de manuel peuvent ne pas être installées sur un système minimal. Pour certaines commandes intégrées au shell, help cd est plus adapté.

10Atelier guidé — Organiser un projet

  1. Revenir dans le dossier personnel.
  2. Créer le dossier linux_debut puis y entrer.
  3. Créer notes.txt et vérifier sa présence.
  4. Renommer le fichier en introduction_linux.txt.
  5. Créer exercices et y déplacer le fichier.

cd ~

cd linux_debut
touch notes.txt

mv -i notes.txt introduction_linux.txt

linux_debut/└── exercices/ └── introduction_linux.txt
Vérification : cat n’affiche rien, car le fichier créé avec touch est vide.

19TP intégrateur complexe — Audit et archivage d’un projet Linux

Contexte professionnel. Vous êtes technicien(ne) informatique. Votre responsable vous confie la préparation d’un espace de travail pour une équipe de développement. Vous devez créer l’arborescence, produire des documents, trier les fichiers, préparer des sauvegardes et générer un rapport d’audit exclusivement à l’aide du terminal Linux.

Durée indicative

90 à 120 minutes

Modalité

Individuel, terminal Bash

Livrables

Arborescence finale, rapport, historique de commandes et réponses argumentées

Sécurité : effectuez tout le TP uniquement dans ~/tp_linux_integrateur. N'utilisez ni sudo ni rm -rf. Vérifiez votre emplacement avec pwd avant les suppressions. Si le dossier existe déjà, choisissez un autre nom : ne supprimez pas vos anciens travaux.

Mission 1 — Préparer l'environnement (15 points)

  1. À partir du répertoire personnel, créez en une seule commande l’arborescence projet/{sources,documents,archives,rapports,temporaires} dans tp_linux_integrateur. Vous pouvez utiliser plusieurs commandes si votre shell ne prend pas en charge les accolades.
  2. Affichez le chemin absolu du répertoire de travail et listez les dossiers, y compris les fichiers cachés.
  3. Créez dans sources trois fichiers vides : app.py, config.txt et test.py. Créez aussi un fichier caché .suivi dans projet.
  4. Depuis documents, accédez à sources par un chemin relatif, puis revenez au dossier précédent avec cd -.

Mission 2 — Produire et manipuler des données (20 points)

  1. À l’aide de echo et des redirections, créez documents/equipe.txt contenant exactement trois lignes : Amine - Developpement, Sarah - Tests, Lina - Documentation.
  2. Créez documents/consignes.txt avec deux lignes : Verifier les fichiers et Preparer la sauvegarde.
  3. Affichez le contenu de ces deux fichiers avec cat. Ajoutez une quatrième ligne à equipe.txt sans écraser les précédentes.
  4. Copiez consignes.txt vers archives/consignes_backup.txt avec confirmation en cas d'écrasement. Renommez sources/config.txt en parametres.txt.

Mission 3 — Traiter les flux et créer un rapport (25 points)

  1. Depuis projet, générez rapports/inventaire.txt avec la liste détaillée des fichiers de sources en utilisant ls -l et >.
  2. Ajoutez au rapport, sans effacer l'inventaire, la liste des éléments de documents à l'aide de >>.
  3. Utilisez un pipe | pour filtrer les lignes de documents/equipe.txt contenant le mot Tests avec grep. Redirigez le résultat vers rapports/tests.txt.
  4. Utilisez cat avec une redirection d'entrée < pour afficher le contenu de rapports/tests.txt.
  5. Provoquez volontairement une erreur de lecture d'un fichier inexistant et redirigez uniquement son message d'erreur vers rapports/erreurs.txt à l'aide de 2>. Vérifiez le contenu obtenu.
  6. Consultez man ls ou man grep, puis identifiez et expliquez une option utile que vous n'aviez pas encore utilisée.
Nouvelle commande utile pour le TP : grep recherche des lignes correspondant à un motif. Exemple : cat fichier.txt | grep "Tests". Si man n'est pas installé dans votre environnement, utilisez ls --help et signalez cette adaptation dans votre compte rendu.

Mission 4 — Sauvegarder, nettoyer et contrôler (20 points)

  1. Copiez récursivement le répertoire documents dans archives sous le nom documents_backup.
  2. Déplacez sources/test.py dans temporaires, puis renommez-le test_ancien.py.
  3. Créez un répertoire vide temporaires/a_supprimer, puis supprimez-le avec rmdir.
  4. Supprimez temporaires/test_ancien.py avec rm -i en confirmant l'opération.
  5. Contrôlez l'existence des sauvegardes, du rapport et du fichier caché. Expliquez pourquoi rmdir ne peut pas supprimer un répertoire non vide.

Mission 5 — Analyse et justification (20 points)

  1. Expliquez avec des exemples issus du TP la différence entre un chemin absolu et un chemin relatif.
  2. Comparez >, >>, <, 2> et |.
  3. Expliquez pourquoi la sauvegarde par cp -r est différente d'un déplacement par mv.
  4. Indiquez les précautions à prendre avant toute suppression et décrivez le rôle de l'invite Linux (utilisateur, machine, répertoire, symbole $ ou #).
