Leçon 5

Algèbre de Boole et logique numérique

Comprendre comment les valeurs Vrai/Faux et les opérateurs logiques permettent à un ordinateur de prendre des décisions, de construire des circuits numériques et d'exprimer des règles utilisées en programmation et en cybersécurité.

Objectifs d’apprentissage. À la fin de ce chapitre, l’étudiant sera capable de :
  • définir une variable booléenne et relier Vrai/Faux aux valeurs 1/0 ;
  • utiliser les opérateurs NON (NOT), ET (AND), OU (OR) et OU exclusif (XOR) ;
  • construire et interpréter une table de vérité ;
  • évaluer une expression logique étape par étape ;
  • traduire une condition exprimée en français en expression booléenne ;
  • appliquer les principales lois de l’algèbre de Boole ;
  • comprendre le rôle des portes logiques dans les circuits numériques ;
  • relier la logique booléenne aux conditions de programmation et aux règles de contrôle d’accès en cybersécurité.

1. Pourquoi l’algèbre de Boole en informatique ?

Un ordinateur manipule des données binaires, mais il doit aussi prendre des décisions. Une condition peut être vraie ou fausse : un mot de passe est correct ou incorrect, un utilisateur possède ou non une autorisation, un fichier existe ou n’existe pas.

Condition→Vrai / Faux→Opération logique→Décision
Idée essentielle. L’algèbre de Boole est une algèbre dans laquelle une variable ne prend que deux états. On les note généralement 0 et 1 ou Faux et Vrai.
Valeur logiqueNotation numériqueInterprétation possible
Faux0Condition non satisfaite, interrupteur ouvert, permission absente
Vrai1Condition satisfaite, interrupteur fermé, permission présente

2. Variables booléennes

Une variable booléenne représente une information qui possède seulement deux valeurs possibles.

A = utilisateur authentifié

A = 1 si l’utilisateur est authentifié ; A = 0 sinon.

B = compte actif

B = 1 si le compte est actif ; B = 0 sinon.

C = fichier chiffré

C = 1 si le fichier est chiffré ; C = 0 sinon.

D = alerte détectée

D = 1 si une alerte est présente ; D = 0 sinon.

Attention au contexte. Le chiffre 1 ne signifie pas toujours « autorisé » et 0 ne signifie pas toujours « interdit ». Ils représentent simplement les deux états définis par le problème.

3. L’opérateur NON — NOT

L’opérateur NON inverse une valeur logique. Si A est vraie, NON A est fausse ; si A est fausse, NON A est vraie.

NON A = ¬A = A̅
ANON A
01
10
Exemple

A signifie « le compte est actif ». Si A = 1, alors ¬A = 0. La proposition « le compte n’est pas actif » est donc fausse.

4. L’opérateur ET — AND

L’opérateur ET donne 1 uniquement lorsque toutes les conditions sont vraies.

A ET B = A ∧ B = A · B
ABA ET B

Exemple — accès à une ressource

A = « utilisateur authentifié » et B = « compte actif ». La règle A ET B autorise la suite seulement lorsque les deux conditions valent 1.

Astuce. Pour ET, cherchez le cas où tout est vrai. Un seul 0 suffit pour obtenir 0.

5. L’opérateur OU — OR

L’opérateur OU donne 1 lorsqu’au moins une des conditions est vraie. Il s’agit du OU inclusif : les deux conditions peuvent également être vraies.

A OU B = A ∨ B = A + B

Exemple

Une notification est envoyée si une connexion inhabituelle OU plusieurs échecs d’authentification sont détectés. Une seule des deux conditions suffit.

6. OU exclusif — XOR

Le OU exclusif est vrai lorsque les deux entrées sont différentes. Si elles sont identiques, le résultat vaut 0.

A XOR B = A ⊕ B

Exemple

A = 1 et B = 0 : A ⊕ B = 1. Mais si A = 1 et B = 1 : A ⊕ B = 0.

8. Expressions booléennes

Plusieurs opérateurs peuvent être combinés pour former une expression logique.

F = A ∧ (B ∨ ¬C)

Pour l’évaluer correctement, on calcule les sous-expressions progressivement. Les parenthèses rendent l’ordre explicite.

Exemple détaillé

Soit A = 1, B = 0 et C = 0. Calculons F = A ∧ (B ∨ ¬C).

1. ¬C = ¬0 = 1 2. B ∨ ¬C = 0 ∨ 1 = 1 3. A ∧ 1 = 1 ∧ 1 = 1 Donc F = 1.
Méthode. Commencez par les parenthèses et les négations, puis calculez les autres opérations. Pour éviter les erreurs, écrivez chaque résultat intermédiaire.

9. Construire une table de vérité

Une table de vérité énumère toutes les combinaisons possibles des variables d’entrée et calcule le résultat de l’expression pour chacune.

Avec n variables, il existe 2n combinaisons. Deux variables donnent 2² = 4 lignes ; trois variables donnent 2³ = 8 lignes.

9.1 Exemple : F = A ∧ ¬B

AB¬BF = A ∧ ¬B

1011

9.2 Méthode systématique

  1. Identifier le nombre de variables.
  2. Créer les 2n combinaisons possibles.
  3. Ajouter une colonne pour chaque sous-expression utile.
  4. Calculer de gauche à droite selon la structure de l’expression.
  5. Vérifier la colonne finale.

10. Traduire une situation en expression logique

Une compétence importante consiste à passer d’une règle écrite en langage naturel à une expression booléenne.

Situation

Un utilisateur peut accéder à une ressource s’il est authentifié ET si son compte est actif.

Définissons A = authentifié et C = compte actif.

Accès = A ∧ C
Situation avec négation

Une opération est acceptée si l’utilisateur est authentifié ET si le compte n’est PAS bloqué.

A = authentifié, B = compte bloqué.

Acceptée = A ∧ ¬B
À vous. Une alerte doit être générée si une connexion inhabituelle est détectée OU si le nombre d’échecs dépasse un seuil. Définissez deux variables booléennes et écrivez l’expression correspondante.

11. Portes logiques et circuits numériques

Les opérateurs booléens possèdent une représentation matérielle : les portes logiques. Elles reçoivent des signaux binaires en entrée et produisent un signal binaire en sortie.

NOT

Une entrée, une sortie. La sortie est l’inverse de l’entrée.

AND

La sortie vaut 1 uniquement si toutes les entrées valent 1.

OR

La sortie vaut 1 si au moins une entrée vaut 1.

XOR

Pour deux entrées, la sortie vaut 1 lorsqu’elles sont différentes.

Entrées binaires→Portes logiques→Expression booléenne→Sortie

12. Lois fondamentales de l’algèbre de Boole

Les lois booléennes permettent de reconnaître des expressions équivalentes et préparent le chapitre consacré à la simplification logique.

LoiFormeIdée
IdentitéA ∧ 1 = A ; A ∨ 0 = ALa valeur reste A.
DominationA ∧ 0 = 0 ; A ∨ 1 = 10 domine ET ; 1 domine OU.
IdempotenceA ∧ A = A ; A ∨ A = ARépéter A ne change rien.
ComplémentA ∧ ¬A = 0 ; A ∨ ¬A = 1A et son contraire.
Double négation¬(¬A) = ADeux inversions redonnent A.
CommutativitéA ∧ B = B ∧ A ; A ∨ B = B ∨ AL’ordre des variables peut être échangé.
Associativité(A ∧ B) ∧ C = A ∧ (B ∧ C)Le regroupement peut changer sans changer le résultat.
DistributivitéA ∧ (B ∨ C) = (A ∧ B) ∨ (A ∧ C)Principe comparable à une distribution algébrique.
Vérification simple

Pour A = 0 : A ∨ ¬A = 0 ∨ 1 = 1. Pour A = 1 : A ∨ ¬A = 1 ∨ 0 = 1. L’expression est donc toujours vraie.

13. Introduction aux lois de De Morgan

Les lois de De Morgan montrent comment transformer la négation d’une expression composée. Elles seront approfondies dans le chapitre de simplification.

¬(A ∧ B) = ¬A ∨ ¬B
¬(A ∨ B) = ¬A ∧ ¬B
Interprétation

« Il n’est pas vrai que A et B soient tous les deux vrais » signifie qu’au moins l’un des deux est faux.

Erreur fréquente. Lorsque la négation traverse les parenthèses, ET devient OU et OU devient ET, et chaque variable est niée.

Les conditions utilisées dans les programmes reposent directement sur la logique booléenne.

Les langages de programmation utilisent des syntaxes différentes, mais le raisonnement reste le même : produire une valeur vraie ou fausse puis choisir une action.

15. Connexion avec la cybersécurité

La logique booléenne est directement pertinente en cybersécurité, car de nombreuses décisions de sécurité reposent sur plusieurs conditions.

Authentification

Combiner des conditions liées à l’identité, à l’état du compte ou à une étape supplémentaire de vérification.

Contrôle d’accès

Exprimer des règles indiquant dans quelles conditions une action est autorisée ou refusée.

Filtrage

Combiner plusieurs critères pour décider si une donnée ou un événement correspond à une règle.

Détection

Construire des conditions à partir de plusieurs indicateurs pour produire une alerte.

Exemple conceptuel. Soit A = utilisateur authentifié, R = rôle autorisé et B = compte bloqué. Une politique simplifiée peut être écrite : Accès = A ∧ R ∧ ¬B. Cette expression décrit seulement la logique de décision ; dans un véritable système, les politiques de sécurité sont généralement plus détaillées.
Principe de sécurité. Une règle logique mal formulée peut produire une décision différente de celle attendue. Il est donc important de définir précisément chaque variable, de vérifier toutes les combinaisons pertinentes et de tester les cas limites.

16. Méthode de résolution

  1. Définir les variables et ce que signifient 0 et 1.
  2. Repérer les mots logiques : NON, ET, OU, exactement un, etc.
  3. Écrire l’expression avec des parenthèses si nécessaire.
  4. Décomposer l’expression en sous-expressions.
  5. Calculer ou construire la table de vérité.
  6. Vérifier quelques cas simples.
  7. Interpréter le résultat dans le contexte du problème.
Variables→Expression→Table / calcul→Vérification→Décision

17. Exercices guidés

A. Comprendre les opérateurs

1. Calculer ¬A lorsque A = 0, puis lorsque A = 1.
2. Calculer A ∧ B, A ∨ B et A ⊕ B pour A = 1 et B = 0.
3. Pour quelles valeurs de A et B l’expression A ∧ B vaut-elle 1 ?
4. Quelle différence existe entre OU et XOR lorsque A = B = 1 ?

B. Évaluer des expressions

5. A = 1, B = 0. Calculer ¬A ∨ B.
6. A = 1, B = 1, C = 0. Calculer A ∧ (B ∨ C).
7. A = 0, B = 1, C = 0. Calculer (A ∨ B) ∧ ¬C.
8. A = 1, B = 0, C = 1. Calculer (A ⊕ B) ∧ C.

C. Tables de vérité

9. Construire la table de vérité de F = ¬A ∨ B.
10. Construire la table de vérité de F = A ∧ (B ∨ C).
11. Construire la table de vérité de F = (A ∨ B) ∧ ¬C.

D. Traduction

12. Écrire une expression : « l’accès est accordé si le compte est actif ET si l’utilisateur est authentifié ».
13. Écrire une expression : « l’alerte est produite si A OU B est vrai, mais pas si les deux sont vrais ».
14. Écrire une expression : « l’action est autorisée si A est vrai ET si B est faux ».

E. Lois booléennes

15. Simplifier A ∧ 1.
16. Simplifier A ∨ 0.
17. Simplifier A ∧ ¬A.

18. Mini étude de cas — règle de contrôle d’accès

Une application utilise trois variables :

  • A : l’utilisateur est authentifié ;
  • R : l’utilisateur possède le rôle requis ;
  • B : le compte est bloqué.

La règle est :

Accès = A ∧ R ∧ ¬B
  1. Expliquer le rôle de chaque variable.
  2. Calculer l’accès pour A = 1, R = 1, B = 0.
  3. Calculer l’accès pour A = 1, R = 0, B = 0.
  4. Calculer l’accès pour A = 1, R = 1, B = 1.
  5. Construire la table de vérité complète de la règle.
  6. Expliquer en une phrase dans quelles conditions l’accès vaut 1.
Objectif. Passer d’une règle écrite à une expression logique, puis utiliser la table de vérité pour vérifier que toutes les combinaisons produisent le comportement attendu.

19. Défi de synthèse

Un système simplifié produit une alerte selon trois indicateurs : A = connexion inhabituelle, E = plusieurs échecs récents, C = appareil connu. On définit :

Alerte = (A ∨ E) ∧ ¬C
  1. Expliquer l’expression avec des mots.
  2. Calculer le résultat pour A=1, E=0, C=0.
  3. Calculer le résultat pour A=0, E=1, C=1.
  4. Construire la table de vérité complète.
  5. Identifier les lignes où l’alerte vaut 1.
  6. Proposer une phrase claire décrivant exactement la règle.

20. Synthèse

  • Une variable booléenne possède deux états : 0/1 ou Faux/Vrai.
  • NON inverse une valeur logique.
  • ET vaut 1 lorsque toutes les conditions sont vraies.
  • OU vaut 1 lorsqu’au moins une condition est vraie.
  • XOR vaut 1, pour deux entrées, lorsqu’elles sont différentes.
  • Une expression booléenne combine plusieurs variables et opérateurs.
  • Une table de vérité permet de vérifier toutes les combinaisons possibles.
  • Avec n variables, une table complète contient 2n lignes.
  • Les lois booléennes permettent de transformer des expressions sans modifier leur résultat.
  • Les lois de De Morgan transforment la négation d’un ET en OU des négations, et inversement.
  • La logique booléenne est utilisée dans les circuits, les programmes et les règles de décision.
  • En cybersécurité, elle aide notamment à raisonner sur l’authentification, le contrôle d’accès, le filtrage et la détection.
